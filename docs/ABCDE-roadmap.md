# ABCDE Roadmap

**Program:** Vortex C30.9 — ABCDE Convergence Program

ABCDE is the master convergence roadmap. B1/B2 prospective evidence is one track inside the program, not the whole Vortex roadmap.

`A Architecture -> B Evidence -> C Validation -> D Cross-Domain -> E Productization`

The tracks advance in parallel where doing so does not contaminate prospective evidence:

`A_integration || B_prospective || C_validation || D_generalization || E_productization`

## A — Core Architecture & Integration

Scope:

- evidence/reality integration;
- domain-intelligence boundary;
- Vortex decision plane;
- governed authorization/execution boundary;
- return of real outcomes to the evidence layer;
- VCRF/reference decision semantics;
- Decision API;
- immutable receipts;
- `known_at` / information-cutoff firewall;
- authority separation.

Exit direction:

- canonical repositories contain the reference architecture and implementation lineage;
- real adapters preserve authority boundaries;
- Vortex outage or abstention cannot silently change an independent execution baseline.

## B — Prospective Evidence Program

Primary tracks:

- B1 — domain/evidence-side prospective cases;
- B2 — governed execution/AgentOps prospective cases.

Public prospective evidence is governed by frozen acquisition and scoring protocols.

Infrastructure readiness does not increment a prospective counter. Only natural operational events satisfying the pre-outcome admission protocol are eligible.

## C — Scientific Validation

Scope includes:

- benchmark comparisons;
- prospective NOAA-style programs;
- prospective macro/market programs where separately frozen;
- calibration;
- ablations;
- falsification;
- baseline comparison;
- statistical uncertainty/significance;
- transition and horizon behavior.

B1/B2 are prospective probes. They do not replace broader scientific validation.

## D — Cross-Domain Generalization

Cross-domain demos establish architectural portability only.

They do not establish empirical universal generalization.

A domain counts toward empirical generalization only when it becomes a controlled validation track with explicit evidence, baseline, outcome, and scoring semantics.

## E — Productization / Vortex OS

Scope:

- Decision Plane / API;
- operator console;
- domain adapters;
- SDK;
- evidence/RIG connectors;
- governed execution integration;
- evidence/receipt ledger;
- deployment;
- observability;
- governance;
- licensing;
- FinBridge/enterprise integration.

Productization may proceed while scientific evidence is incomplete, but product claims must remain bounded by the actual evidence state.

## Immediate convergence definition

The current convergence phase is not complete merely because repositories exist.

The immediate phase is materially complete only when:

1. real repository/component integration works;
2. B1/B2 producers can operate prospectively in SHADOW under frozen admission;
3. scientific validation continues without moved gates;
4. multiple domains progress from demo portability toward controlled empirical validation;
5. the public/private GitHub structure is canonical enough to continue the program without chat-only state.

## Permanent claim boundary

A mature architecture and deployable product do not imply universal predictive superiority.

A successful prospective track does not imply arbitrary cross-domain generalization.

Every claim remains scoped to its evidence.
